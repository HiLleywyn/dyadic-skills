# Dyadic Skills

[Skills](https://github.com/HiLleywyn/dyadic-skills) · [Agents](https://github.com/HiLleywyn/dyadic-agents) · [Plugins](https://github.com/HiLleywyn/dyadic-plugins)

61 skills: a mirror of Dyadic's 37 official catalog skills plus repository-authored and imported skills for lley.cat, Ward, Windows, Docker, Linux and development work. Each skill folder holds its own `SKILL.md` and supporting resources (references, scripts, templates, metadata, licenses). Category folders are navigation, not installable packages. Nothing here contains credentials or installs a service.

## Validate and build

Requires Python 3.11+ and PyYAML.

```sh
python -m pip install PyYAML
python dyadic/scripts/verify_catalog_mirror.py           # mirrored files match dyadic/catalog-source.json
python tools/catalog.py check                            # frontmatter, IDs, links, provenance hashes
python .lley/run.py                                      # test suite; writes reports/catalog.xml and fails on any skip
python tools/catalog.py build                            # dist/<skill-id>.zip, dist/checksums.json, dist/collection.zip
python dyadic/security/scripts/validate_security_suite.py   # security suite manifests, schema and links
```

Builds are deterministic and never execute bundled scripts. Security skill exports include the shared standards from `dyadic/security/_shared/` under `references/standards/`.

## Using a skill

Read only the relevant `SKILL.md` and the references it asks for, and keep the whole skill folder together. For runtimes that load skill folders (for example a Codex `skills` directory), copy the individual skill folder, not its category folder. Sibling skills may link to each other; install the ones a workflow calls for. Do not run bundled scripts merely to install or inspect a skill.

In Dyadic, upload an individual `dist/<skill-id>.zip` through the reviewed Store import; `dist/collection.zip` is a download container to extract first. Dyadic's package-source resolver accepts public GitHub URLs but rejects any URL with a query string, so lley.cat folder links cannot be imported directly. Host-oriented skills (Windows, Docker, operator workflows) still need the actual host tools, and installing a skill does not enable plugins, grant permissions or change model selections.

## Relationship to Dyadic

The 37 packages under `dyadic/iris/` and `dyadic/security/` are owned by Dyadic's `catalog/skills/`. Change them there, commit, then run Dyadic's `tools/sync_dyadic_skills.py <this checkout>` (check mode by default; `--write` copies files and rewrites `dyadic/catalog-source.json`). Keep `provenance.json` consistent with that receipt. The sync tool refuses a target without `dyadic/README.md` and stops on unexpected extra files inside mirrored packages. Everything else in this repository is maintained here directly.

`tools/catalog.py`, `tests/` and `.lley/run.py` are shared with dyadic-agents and dyadic-plugins; apply changes to all three. dyadic-agents locks the exact hashes of the skills its specialists bundle (`compatibility/skill-dependencies.json` there), so a skill change may need a reviewed lock refresh in that repository.

## CI

[.github/workflows/ci.yml](.github/workflows/ci.yml) runs the mirror verifier, `python .lley/run.py` and `python tools/catalog.py build` on every push and pull request. `.lley/pipeline.json` declares the equivalent stage for the lley.cat mirror's runner. Neither deploys anything or changes Dyadic's Store.
